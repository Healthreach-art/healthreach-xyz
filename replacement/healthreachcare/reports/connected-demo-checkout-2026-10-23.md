HealthReachCare connected checkout update — 2026-10-23

Implemented in the existing Sites app, using the selected new Firebase identity, shared D1 records and existing private R2. No sample providers, stock, prices, patients or successful payments were seeded into the hosted app.

Authenticated checkout is enabled only when the server runtime flag HRC_SIMULATED_PAYMENTS_ENABLED is true. Every generated payment has simulated=true, a DEMO reference, integer amountMinor, an internal-simulator provider and no-charge wording. Real payment/payout flags remain false. No payment gateway, billing setting, Firebase users, DNS or old deployment was changed.

Fixed-price homecare and doctor reservations validate saved provider publication, approval, service prices, future time and capacity. Payment attempts are persisted; only a successful demo outcome confirms the request and notifies its assigned provider. Unpaid care/appointment holds are excluded from provider work queues. Concurrent mutations use the existing D1 compare-and-swap version check. Paid medication checkout creates the order only after success, validates catalogue snapshots/stock, and creates a simulated delivery task only at dispatch readiness. Prescription approval and identity safeguards remain before payment/fulfilment.

Homecare categories with no published provider now open a real availability-request form rather than a dead-end notice. The request is stored unpaid with no invented price/provider. Admin may offer an eligible published provider's fixed rate; the patient explicitly reviews/pays. Provider accounts must save services, actual hours/days and prices; an authorized recently reauthenticated admin must review/publicize the listing. Current absence of eligible providers is not bypassed.

Admin UI adds reference-style activity/service charts, registered-user summary, recent conversations, withdrawal queue, separate homecare/doctor directory views, financial records, withdrawals and reports routes, literal search/status filters and CSV export. Counts use saved records. Demo payments are excluded from real withdrawable balances; live bank transfers, scheduled payouts and verified settlement are not implemented by this change. A withdrawal screen with no eligible funds does not fabricate a request.

Connected-account policy acknowledgements have a separate version from the isolated demo policies. Old acknowledgements and audit records are retained. These drafts do not claim legal/regulatory compliance.

Validation: lint, TypeScript and the existing full automated suite run during implementation; added isolated authenticated D1 flows for homecare/demo payment/provider queue/status/text persistence, doctor availability/booking/payment/overlap, medication checkout/failure/success/stock/snapshot/dispatch, publication authorization and no-provider availability requests. Rendering/handler tests cover the new admin views and homecare retry flow. Build and final publication results are reported separately in the conversation.

Remaining: actual owner/provider sign-in and physical service testing; verified inventory and published eligible providers; live payment gateway and settlement/payout integration; driver acceptance/proof-of-delivery extensions in the authenticated adapter; protected voice/attachment service-message integration; requested per-login admin email challenge; registration/verification and main-owner transfer to admin@healthreachcare.co.za. The three-click logo entry remains a sign-in shortcut, never an authorization mechanism. Cloudflare custom-domain cutover and Sites data/file handoff remain pending. The old app and data remain preserved.
